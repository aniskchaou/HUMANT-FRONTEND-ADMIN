1. Product Overview

Humant is a full Human Resource Management System (HRMS) that centralizes people operations across recruitment, employee administration, compensation workflows, documentation, compliance, and team communication.

In short: Humant replaces disconnected spreadsheets, email chains, and single-purpose tools with one organized operational system where each role sees exactly what they need.

  • Contract and document management
  • Onboarding and offboarding

Pay

4. System Requirements

Runtime

  • Node.js 14.x or 16.x (Angular 11 compatibility)
  • npm 6+ or 8+
  • Java 11 JDK (Spring Boot 2.5 backend)

Database

  • PostgreSQL 12+ — recommended for production
  • MySQL 8+ — supported alternative
  • SQLite — zero-config for local development
The GUI launcher (Step 1) checks prerequisites automatically and offers one-click install via Winget (Windows), Homebrew (macOS), or apt-get (Linux).

5. Quick Start

Three approaches — choose the one that matches your context.

Option A — GUI Launcher (recommended)

Double-click launcher.bat (Windows) or run ./launcher.sh (macOS/Linux). The browser opens at http://localhost:3030. Follow the 4-step wizard.

Option B — Manual CLI

npm install --legacy-peer-deps

# PostgreSQL database
psql -U postgres -c "CREATE DATABASE humant;"

# Backend (separate terminal)
cd backend && ./mvnw spring-boot:run

# Frontend
npm run serve -- --port 4201

Frontend: http://localhost:4201  |  Backend API: http://localhost:8080

6. GUI Launcher

The launcher is a zero-dependency Node.js server that provides a browser-based control panel at http://localhost:3030.

4-step wizard

Step 1 — Prerequisites

Checks Node.js, npm, Java 11, and Git. Shows version info. Offers auto-install via OS package manager.

Step 2 — Database

Select SQLite (zero-config), PostgreSQL, or MySQL. Configure host/port/credentials. Config saved to backend/launcher-config.json.

Step 3 — Install

Runs npm install --legacy-peer-deps for Angular. Progress bar tracks installation. Backend Maven deps resolve automatically at start.

Step 4 — Launch

Start/stop button pair. Boots Angular on 4201 and Spring Boot on 8080 simultaneously. Live activity log at the bottom.

Note: The launcher passes database env vars to the backend process on start. Changing the dialect after first run may require spring.jpa.hibernate.ddl-auto=create temporarily to reinitialize schema.

8. Database Setup

PostgreSQL (default)

CREATE DATABASE humant;
-- application.properties default: localhost:5432, user=postgres

Backend config: backend/src/main/resources/application.properties. Override at runtime via HUMANT_DATASOURCE_* environment variables.

SQLite (zero-config)

Set dialect to sqlite in the launcher. The backend creates humant.db automatically. No setup required.

MySQL

CREATE DATABASE humant CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

Set dialect to mysql in the launcher and provide host/port/credentials. The MySQL JDBC driver is already bundled in pom.xml.

9. Deployment Generator

The deployment generator creates a self-contained folder ready for upload to any JVM-capable server or cloud platform.

node generate-deployment-version.js
# or double-click
generate-deployment-version.bat

Opens a browser UI at http://localhost:3040.

What gets generated

frontend/

Production Angular build output (dist/my-app-angular contents), ready for Nginx or CDN.

backend/humant.jar

Packaged Spring Boot JAR from backend/target — runs with java -jar.

config/application-production.properties

Production Spring Boot properties with your selected database, Stripe keys, and public URL.

config/nginx.conf.example

Same-origin Nginx config: serves frontend/ at root and proxies /api to the backend.

10. VPS Deployment

sudo apt update
sudo apt install -y nginx postgresql openjdk-11-jre-headless ufw

# Upload deployment bundle to server
scp -r deployment-builds/humant-deployment-* user@server:/var/www/humant/

# Create database
sudo -u postgres psql -c "CREATE DATABASE humant;"

# Copy nginx config
sudo cp /var/www/humant/config/nginx.conf.example /etc/nginx/sites-available/humant
sudo ln -s /etc/nginx/sites-available/humant /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

# Start backend (systemd service recommended for production)
java -jar /var/www/humant/backend/humant.jar \
  --spring.config.location=file:/var/www/humant/config/application-production.properties

11. Nginx Configuration

The generated nginx.conf.example uses a same-origin reverse proxy model:

server {
    listen 80;
    server_name your-domain.example;

    root /var/www/humant/frontend;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

With this setup, the Angular app calls /api relative to the same origin, so no CORS configuration is needed and the HUMANT_DATASOURCE_URL in the Angular build resolves automatically.

13. HR Modules

Employee

Create and manage employee profiles with personal details, employment info, and linked records. The central entity for all HR operations.

Attendance

Daily attendance records, biometric import support, and monthly summaries. Feeds into payroll pre-processing.

Leave

Leave request workflow with type-based balance tracking. Managers receive and approve requests. Integrates with holiday calendar.

Contract

Employee contract templates with type classification (permanent, fixed-term, freelance). Tracks start/end dates and renewal events.

Document

Document repository per employee. Supports multi-version uploads, category tagging, and access-level controls (admin-only / employee-visible).

Onboarding

Checklist-based onboarding with task assignment to HR and the new hire. Tracks completion percentage and surfaces blockers.

Warning / Complaint

Formal record of workplace warnings and complaints with severity classification, resolution notes, and manager sign-off.

Notice

Internal notice board with target audience (department, designation, or all). Publication date tracking and acknowledgement status.

Termination / Resign

Off-boarding workflows covering exit interviews, clearance checklists, final settlement calculation, and documentation.

14. Payroll Modules

Salary

Payslip

Monthly payslip generation with downloadable PDF output. Includes earnings, deductions, and net pay summary.

Loan

Expense

17. Architecture

Frontend — Angular 11

SPA at repository root. Builds to dist/my-app-angular. Development proxy at proxy.conf.json forwards /api to port 8080. The URL_BASE in src/app/main/urls/urls.ts resolves to the same origin in production.

Backend — Spring Boot 2.5

REST API in backend/. Spring Data JPA with Hibernate. Spring Security JWT. PostgreSQL default with SQLite and MySQL support via env-var dialect switching.

Same-origin deployment: Host the Angular build behind Nginx and proxy /api to the Spring Boot service on port 8080. This avoids CORS and keeps the frontend API base URL working without code changes.

18. API Overview

The Spring Boot backend exposes a REST API on port 8080. Swagger UI is available at http://localhost:8080/swagger-ui.html when running locally.

19. FAQ

Does Humant require PostgreSQL?

PostgreSQL is the default and recommended database. The launcher can switch to MySQL or SQLite for zero-configuration local development. Production deployments should use PostgreSQL or MySQL for reliability and concurrent access support.

Why does npm install fail?

angular-datatables@10 has a peer dependency conflict with Angular 11 on npm 7+. Always install with npm install --legacy-peer-deps. The launcher does this automatically in Step 3.

What Java version is required?

Java 11 is required by Spring Boot 2.5. The Maven wrapper (mvnw / mvnw.cmd) handles Maven automatically — no global Maven installation is needed.

How do I deploy to a cloud server?

Use the Deployment Generator (port 3040) to build a bundle. Then upload the bundle to your server and use the included Nginx config to serve frontend files and proxy /api to the backend JAR.

How do I change the default admin credentials?

Default credentials are seeded via backend/src/main/resources/data.sql. Edit that file before first run or update credentials through the admin panel after the first login.
